# SignalRVisualizer — учебный проект ASP.NET Core MVC + SignalR + PostgreSQL

Проект показывает полный цикл обновления HTML-таблицы на странице ASP.NET Core MVC через **SignalR** и уведомления PostgreSQL **LISTEN/NOTIFY**.

Главная идея проекта: страница открывается обычным MVC-способом, таблица сразу заполняется из PostgreSQL, а дальнейшие обновления могут идти двумя способами:

1. **Автоматически** — если включена кнопка `Включить SignalR таблицы`, браузер подписан на SignalR-группу канала БД и обновляет таблицу после `NOTIFY`.
2. **Вручную** — кнопка `Обновить таблицу через SignalR` делает разовый запрос через Hub и перечитывает таблицу даже без уведомления из БД.

## Подробное описание файлов

### [Program.cs](Program.cs)

Это точка входа приложения. В нем настраиваются сервисы и маршруты.

Главные части:

```csharp
builder.Services.AddControllersWithViews();
builder.Services.AddSignalR();
builder.Services.AddHostedService<ИмитацияРаботыСервера>();
builder.Services.AddHostedService<ПрослушкаКаналовБД>();
```

Что это значит:

- `AddControllersWithViews()` включает MVC-контроллеры и Razor-представления.
- `AddSignalR()` регистрирует SignalR.
- `AddHostedService<ИмитацияРаботыСервера>()` запускает учебный фоновый сервис.
- `AddHostedService<ПрослушкаКаналовБД>()` запускает прослушку PostgreSQL.

Маршруты Hub:

```csharp
app.MapHub<ТаблицаSignalRHub>("/ТаблицаSignalRHub");
app.MapHub<УчебныйSignalRHub>("/УчебныйSignalRHub");
```

Эти адреса должны совпадать с адресами в [wwwroot/js/учебный-signalr.js](wwwroot/js/учебный-signalr.js).

---

### [Controllers/ГлавнаяController.cs](Controllers/ГлавнаяController.cs)

Контроллер отвечает за загрузку данных из БД и передачу модели в Razor.

Главные методы:

#### `ПерваяСтраница(...)`

Полная загрузка страницы:

```text
открытие страницы → чтение БД → return View(model)
```

#### `ЧастичнаяОтрисовка(...)`

Partial-загрузка таблицы:

```text
fetch из JS → чтение БД → return PartialView("ТаблицаPartialView", model)
```

#### `ДанныеИзТаблицы(...)`

Внутренний метод, который открывает Npgsql-соединение и выполняет SQL-запрос к таблице:

```sql
SELECT
    "N_поз_ТА",
    "N_ряда",
    "Прав_поток_номер_поковки",
    "Прав_поток_на_поддоне_количество",
    "Прав_поток_на_поддоне_ед_измерения",
    "Лев_поток_номер_поковки",
    "Лев_поток_на_поддоне_количество",
    "Лев_поток_на_поддоне_ед_измерения",
    "Старт"
FROM "_Диспозиция_поковок_ТА"
WHERE "N_поз_ТА" >= 1 AND "N_поз_ТА" <= 4
ORDER BY "N_поз_ТА";
```

Если запрос падает, контроллер не выбрасывает ошибку дальше, а записывает текст ошибки в `model.ОшибкаЗагрузки`. Потом partial показывает эту ошибку в таблице.

---

### [Models/МодельДляСтрокиИзБазы.cs](Models/МодельДляСтрокиИзБазы.cs)

Это модель, которую контроллер передает в View и PartialView.

Содержит:

```csharp
public List<Лист> ЛистДляТаблицыИзБазы { get; set; } = new();
public string? ОшибкаЗагрузки { get; set; }
public DateTime ВремяПоследнейЗагрузки { get; set; } = DateTime.Now;
```

`Лист` — вложенный класс одной строки таблицы. Все поля сделаны строками, чтобы Razor мог безопасно вывести значения без сложного форматирования.

---

### [Views/Главная/ПерваяСтраница.cshtml](Views/Главная/ПерваяСтраница.cshtml)

Главная Razor-страница.

Важные элементы:

- `@model МодельДляСтрокиИзБазы` — страница ожидает модель.
- `@await Html.PartialAsync("ТаблицаPartialView", модель)` — первичная вставка строк таблицы.
- `<tbody id="Таблица">` — именно этот блок заменяется JavaScript при обновлении.
- `const каналСтраницы = ...` — передача имени C#-канала в JS.
- Подключение скриптов:

```html
<script src="~/js/signalr.min.js"></script>
<script src="~/js/учебный-signalr.js" asp-append-version="true"></script>
```

---

### [Views/Главная/ТаблицаPartialView.cshtml](Views/Главная/ТаблицаPartialView.cshtml)

Partial-представление отвечает только за строки таблицы.

Оно умеет отрисовывать три состояния:

1. Есть ошибка загрузки БД.
2. Ошибки нет, но список строк пустой.
3. Есть строки, которые нужно вывести.

Это удобно, потому что один и тот же partial используется и при полной загрузке страницы, и при обновлении через JavaScript.

---

### [Hubs/ТаблицаSignalRHub.cs](Hubs/ТаблицаSignalRHub.cs)

Hub для работы таблицы.

Он содержит три главные операции:

#### `ПодключениеКСтранице(string канал)`

Добавляет текущего клиента в SignalR-группу:

```text
ConnectionId → db_канал:та_34898_n2_channel
```

#### `ОтключениеОтСтраницы(string канал)`

Удаляет клиента из группы. После этого уведомления БД не будут обновлять таблицу в этом браузере.

#### `ЗапроситьРазовоеОбновлениеТаблицы(string канал)`

Нужен для кнопки ручного обновления. Hub подтверждает, что запрос разрешен, и возвращает список таблиц, которые нужно перечитать.

---

### [Services/ПрослушкаКаналовБД.cs](Services/ПрослушкаКаналовБД.cs)

Фоновый сервис прослушки БД.

Как он работает:

1. Читает строку подключения `ТА_34898Н2` из [appsettings.json](appsettings.json).
2. Открывает отдельное подключение к PostgreSQL.
3. Выполняет `LISTEN` для каждого разрешенного канала из [Models/МодельДляОпределенияКаналов.cs](Models/МодельДляОпределенияКаналов.cs).
4. Ждет уведомления через `WaitAsync(...)`.
5. При уведомлении разбирает `payload` на имена таблиц.
6. Накопленные изменения отправляет в SignalR-группу.

Сервис использует задержку 200 мс, чтобы объединить несколько быстрых уведомлений в один пакет. Это полезно, когда БД за короткое время отправляет много `NOTIFY`.

---

### [wwwroot/js/учебный-signalr.js](wwwroot/js/учебный-signalr.js)

Главный клиентский файл.

В нем создаются два SignalR-соединения:

```javascript
const подключение = new signalR.HubConnectionBuilder()
    .withUrl("/УчебныйSignalRHub")
    .withAutomaticReconnect()
    .build();

const подключениеКСтранице = new signalR.HubConnectionBuilder()
    .withUrl("/ТаблицаSignalRHub")
    .withAutomaticReconnect()
    .build();
```

Первое соединение — учебное. Второе — для таблицы PostgreSQL.

Самая важная логика таблицы:

```text
включитьSignalRТаблицы()
выключитьSignalRТаблицы()
обновитьТаблицуЧерезSignalRОдинРаз()
обновитьДанныеТаблицы(причина, таблицы)
```

`обновитьДанныеТаблицы(...)` делает обычный `fetch`:

```javascript
fetch(`/Главная/ЧастичнаяОтрисовка?_=${Date.now()}`, {
    method: "GET",
    headers: {
        "X-Requested-With": "XMLHttpRequest"
    },
    cache: "no-store"
});
```

Потом полученный HTML вставляется в:

```html
<tbody id="Таблица">
```

### [wwwroot/css/учебный-signalr.css](wwwroot/css/учебный-signalr.css)

CSS отвечает за внешний вид страницы:

- карточки;
- кнопки;
- статусные лампочки;
- схему SignalR;
- журнал событий;
- таблицу PostgreSQL;
- горизонтальную и вертикальную прокрутку таблицы.

Для таблицы важны эти свойства:

```css
.обертка-таблицы-базы-данных {
    overflow-x: auto;
    overflow-y: auto;
}

.таблица-базы-данных {
    width: max-content;
    min-width: 100%;
}
```

Они нужны, чтобы широкая таблица не вылезала за границы карточки.

## Как проверить работу проекта

### 1. Запусти проект

Открой решение [SignalRVisualizer.sln](SignalRVisualizer.sln) в Visual Studio 2022 и запусти проект.

Откроется страница:

```text
/Главная/ПерваяСтраница
```

---

### 2. Проверь первичную загрузку таблицы

При открытии страницы таблица должна сразу появиться, даже если SignalR выключен.

Если таблица не загрузилась, смотри блок статуса над таблицей. Там будет текст ошибки подключения или SQL-запроса.

---

### 3. Проверь ручное обновление

Нажми:

```text
Обновить таблицу через SignalR
```

В журнале должно появиться примерно такое событие:

```text
Hub подтвердил разовое обновление. Таблицы: _Диспозиция_поковок_ТА
```

После этого таблица перечитается через `/Главная/ЧастичнаяОтрисовка`.

---

### 4. Проверь автообновление через PostgreSQL NOTIFY

Сначала нажми на странице:

```text
Включить SignalR таблицы
```

Потом в pgAdmin или psql выполни:

```sql
NOTIFY "та_34898_n2_channel", '_Диспозиция_поковок_ТА';
```

Если всё работает, в журнале появится событие из PostgreSQL, а таблица обновится.

## Как добавить новый канал БД

Допустим, нужно слушать еще один канал, например `audit_machines_channel`.

### Шаг 1. Добавить канал в [Models/МодельДляОпределенияКаналов.cs](Models/МодельДляОпределенияКаналов.cs)

```csharp
public const string АудитМашин = "audit_machines_channel";

public static readonly HashSet<string> Allowed = new()
{
    Печь898Н2,
    АудитМашин
};
```

### Шаг 2. Передать нужный канал на нужную страницу

В [Views/Главная/ПерваяСтраница.cshtml](Views/Главная/ПерваяСтраница.cshtml) сейчас передается:

```csharp
МодельДляОпределенияКаналов.Печь898Н2
```

Для другой страницы можно передать другой канал.

### Шаг 3. Отправить NOTIFY из PostgreSQL

```sql
NOTIFY "audit_machines_channel", 'Аудит_машин';
```

## Почему SignalR не читает таблицу сам

В проекте специально разделены обязанности:

| Слой | За что отвечает |
|---|---|
| Controller | Читает БД и формирует модель. |
| Razor PartialView | Превращает модель в HTML. |
| SignalR Hub | Управляет real-time событиями и группами клиентов. |
| BackgroundService | Слушает PostgreSQL и отправляет уведомления в Hub. |
| JavaScript | Получает события и заменяет HTML на странице. |

Такой подход проще переносить в большой промышленный проект. Например, в основном проекте можно сделать один агрегирующий controller endpoint, который будет возвращать несколько partial-блоков сразу.

## Частые проблемы

### Таблица показывает ошибку подключения

Проверь строку подключения в [appsettings.json](appsettings.json):

```json
"ТА_34898Н2": "Host=localhost;Port=443;Username=postgres;Password=postgres8421;SSL Mode=disable;Database=ТА_34898_N°2_HMI"
```

Особенно проверь:

- `Host`;
- `Port`;
- `Username`;
- `Password`;
- `Database`.

---

### NOTIFY отправлен, но таблица не обновилась

Проверь по порядку:

1. На странице нажата кнопка `Включить SignalR таблицы`.
2. Канал в SQL совпадает с каналом в [Models/МодельДляОпределенияКаналов.cs](Models/МодельДляОпределенияКаналов.cs).
3. SQL-команда использует кавычки:

```sql
NOTIFY "та_34898_n2_channel", '_Диспозиция_поковок_ТА';
```

4. Сайт подключен к той же БД, куда отправляется `NOTIFY`.
5. В Visual Studio Output нет ошибок от [Services/ПрослушкаКаналовБД.cs](Services/ПрослушкаКаналовБД.cs).

---

### Ручная кнопка обновляет, а автообновление нет

Это значит, что MVC-загрузка таблицы работает, но проблема именно в цепочке:

```text
PostgreSQL NOTIFY → ПрослушкаКаналовБД → SignalR-группа → браузер
```

Проверь канал, строку подключения и кнопку `Включить SignalR таблицы`.
